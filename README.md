# GREEN Chat — React + TypeScript

Тестовое задание на должность «Фронтенд разработчик React». Автор: Shukurullo Boburov, https://boburov.uz.

Минимальный интерфейс в стиле веб-мессенджера MAX: вход с параметрами GREEN-API, создание чата по номеру телефона, отправка и получение текстовых сообщений. Используются реальные HTTP методы GREEN-API, без собственного backend. API MAX v3 поддерживает унифицированные пути `waInstance…`, как WhatsApp; поэтому тот же клиент работает с обоими мессенджерами при указании apiUrl соответствующего инстанса.

## Локальный запуск

Node.js 22+ и npm.

```sh
npm ci
npm run dev
```

Открыть адрес, который напечатает Vite (обычно http://127.0.0.1:5173).

```sh
npm test
npm run build
npm run preview
```

Production: опубликовать содержимое `dist/` на любом статическом HTTPS-хостинге. Базовый путь относительный, приложение не требует серверного роутинга.

## Подключение и проверка

1. Создайте инстанс MAX или WhatsApp в https://console.green-api.com/ и авторизуйте мессенджер. Убедитесь, что состояние `authorized`.
2. В настройках инстанса включите `incomingWebhook`. Для HTTP polling не назначайте webhookUrl и не запускайте второй потребитель очереди на том же инстансе. На тарифе Developer проверьте ограничения/добавление разрешённого номера.
3. В форме приложения укажите **apiUrl**, **idInstance**, **apiTokenInstance** именно из кабинета. apiUrl: HTTPS-хост вида `https://3100.api.green-api.com` (или `https://api.green-api.com`). Произвольные хосты запрещены, чтобы не передавать токен третьим лицам.
4. Введите телефон получателя с международным кодом. Создайте чат и отправьте текст.
5. Ответьте с другого телефона в MAX / WhatsApp. Ответ автоматически появится в переписке.
6. Переключите чат, проверьте сохранение сообщений в текущей сессии. Нажмите «Выйти»: polling отменяется, данные сессии удаляются из памяти. После перезагрузки потребуется повторный вход.

## Реализация

- React 19 + TypeScript + Vite, без UI-фреймворка, адаптивный двухколоночный чат; на телефоне список и переписка открываются отдельно.
- `src/api.ts`: проверка параметров, SendMessage, ReceiveNotification (long polling), DeleteNotification (подтверждение обработки), нормализация входящих текстов и адресов MAX.
- `src/main.tsx`: состояние сессии, список чатов, сообщения, формы, загрузка и ошибки. Enter отправляет, Shift+Enter добавляет строку.
- Получение выполняется последовательно, с задержкой между запросами и backoff до 30 секунд при ошибке. AbortController отменяет запросы при выходе. Повторное уведомление не дублирует сообщение, даже если подтверждение временно не удалось.
- Ошибка отправки сохраняет текст в поле. Текст выводится средствами React, без HTML-инъекций. Временные метки — локальное время пользователя. Галочка означает принятие запроса API, а не подтверждённую доставку получателю.
- Ключи и переписка не пишутся в localStorage, URL страницы, репозиторий или логи приложения. Токен остаётся в памяти вкладки и отправляется только GREEN-API. Для выполнения задания API вызывается из браузера; ключ виден владельцу браузера в DevTools. В большом production-продукте стоит использовать backend-прокси и полноценную серверную сессию.
- Текстовые сообщения до 4000 символов. Вложения, группы, история до открытия приложения и статусы доставки не входят в задание. Не-текстовые уведомления подтверждаются и пропускаются, чтобы не блокировать очередь. HTTP-очередь является общей для инстанса: используйте отдельный тестовый инстанс.

## Проверка качества

`npm test` проверяет API-контракт, формирование номера, безопасность apiUrl, пустые ответы, ошибки, MAX-адресацию, дедупликацию и отмену polling. Тесты используют подменённый fetch, а не реальные токены. **Живой сценарий с авторизованным инстансом не проверен: на момент подготовки аккаунт GREEN-API отсутствовал.** Это нужно проверить по шагам выше перед окончательной сдачей.
